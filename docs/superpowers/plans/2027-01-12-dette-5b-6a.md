# Dette des étapes 5b et 6a — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** corriger les points mineurs les plus utiles relevés par les revues des étapes 5b (comptes parents) et 6a (banques BPH), sans changer de fonctionnalité.

**Architecture :**

**Spec :**
- `docs/superpowers/specs/2026-12-29-etape-5b-parents-design.md` ;
- `docs/superpowers/specs/2027-01-05-etape-6a-banques-bph-design.md` ;
- les bilans `2026-12-29-etape-5b-bilan.md` et `2027-01-05-etape-6a-bilan.md`.

Ce plan n'ajoute aucune exigence : il remet le code en accord avec ces specs et corrige des tests peu probants. Il a été rédigé par le contrôleur pendant la session autonome de nuit, à partir des points reportés des registres de revue. Ces points n'ont pas encore été validés par l'utilisateur.

**Branche :** `dette-5b-6a`, créée depuis `etape-6a-banques-bph`. Sa PR visera `etape-6a-banques-bph` (PR n° 10).

## Contraintes globales

Ce sont celles du plan 6a, `docs/superpowers/plans/2027-01-05-etape-6a-banques-bph.md`, section « Contraintes globales », qui s'appliquent toutes. On en rappelle l'essentiel :

- **Langue** : interface en français. On tutoie l'élève et l'admin, on vouvoie le parent, et les formulations ne sont pas genrées.
- **Typographie** : U+00A0 avant « : ; ! ? » et à l'intérieur de « ».
- **Base de données** : RPC `security definer` avec `set search_path = ''`. Pour recréer une fonction, on recopie son corps actuel depuis la migration la plus récente.
- **Codes d'erreur** : traduits et testés, sans être sous-chaîne d'un autre code.
- **pgTAP** : chaque test utilise ses propres UUID.
- **Commandes** : préfixer les commandes shell par `export PATH="$HOME/.orbstack/bin:$PATH";` et git par `DEVELOPER_DIR=/Library/Developer/CommandLineTools`. Ne jamais afficher `.env.local`.
- **Commits** : terminés exactement par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Navigateur** : la CSP stricte et la revue axe restent vertes, et les écrans restent utilisables à 375 px.

### Task 1 : page d'accord rejouée après un retrait (5b)

**Problème :** après un retrait de l'accord par le parent, rouvrir l'ancien lien d'accord affiche encore « … peut maintenant utiliser l'application » et le bouton « Créer mon compte parent ». Or le compte de l'enfant reste bloqué.

**Files :**
- Create : `supabase/migrations/20270112000001_accord_retire.sql`
- Modify :
  - `supabase/tests/suivi_parent.test.sql`, ou un nouveau `supabase/tests/accord_retire.test.sql` ;
  - `src/app/accord-parental/[jeton]/page.tsx` ;
  - `src/lib/supabase/types.ts` ;
  - les tests unitaires de la page s'il en existe.

- [ ] **Test pgTAP**
  - `lire_demande_consentement(jeton)` renvoie une nouvelle colonne `retire boolean` : `true` si `retire_le` est renseigné, `false` sinon.
  - Après un retrait, `donner_consentement(jeton)` lève `consentement_retire`. C'est le code existant, sa traduction est à revoir : voir plus bas.
  - Sans retrait, le comportement ne change pas.
- [ ] **Migration** : recréer les deux fonctions à partir de leur corps actuel, dans `20261222000002_consentement.sql`. Vérifier par `grep` qu'aucune migration plus récente ne les redéfinit.
  - `lire_demande_consentement` : la signature de retour change, il faut donc la supprimer puis la recréer, et rétablir ses droits actuels (ouverte à `anon` et `authenticated`, comme aujourd'hui).
  - `donner_consentement` : ajouter `if retire_le is not null then raise exception 'consentement_retire'` avant la mise à jour, après la recherche par empreinte.
- [ ] **Page** : si `demande.retire`, afficher un titre « Accord retiré » et le texte « Vous avez retiré votre accord. Le compte de votre enfant est bloqué et sera supprimé à la date prévue. Pour annuler le retrait, connectez-vous à votre compte parent. », avec un lien « Me connecter » vers `/connexion`. Aucun formulaire, aucun bouton « Créer mon compte parent ».
  - Le message de `consentement_retire` dans `src/lib/erreurs.ts` tutoie l'élève. Sur cette page publique, l'action d'accord doit afficher un message vouvoyé : utiliser la variante `destinataire = 'parent'` de `messageErreur` (étape 6a), en ajoutant si besoin le texte parent « L'accord a été retiré : cette page ne permet plus de le donner. ». Ajouter son test.
- [ ] **Vérifier** : `npm run db:reset && npx supabase gen types typescript --local > src/lib/supabase/types.ts && npm run test:db && npm test && npm run typecheck && npm run lint`, puis `npx playwright test e2e/consentement.spec.ts e2e/parents.spec.ts`.
- [ ] **Commit** : « Affiche l'accord retiré sur la page d'accord rejouée ».

### Task 2 : tests pgTAP plus probants (5b et 6a)

**Files :** `supabase/tests/suivi_parent.test.sql`, `supabase/tests/statut_en_lot.test.sql`, `supabase/tests/garder_statuts.test.sql`, `supabase/migrations/20270112000002_garder_valide.sql` (point c).

- [ ] **a. `suivi_parent`**
  - Créer une tentative **terminée** pour l'enfant, avec `fin` renseignée, pour que :
    - l'assertion « le parent ne lit pas les tentatives » discrimine vraiment, et compte 0 alors qu'une ligne existe ;
    - `progression_enfant` renvoie `derniere_activite` égale à cette `fin` (nouvelle assertion).
  - Tester la garde `retire_par = auth.uid()` d'`annuler_retrait_consentement` : relier un **second parent** à l'enfant par insertion directe en superutilisateur dans `public.lien_parent`. Ce parent tente d'annuler le retrait fait par le premier et doit recevoir `retrait_impossible`.
- [ ] **b. `statut_en_lot`**
  - Créer les questions avec des UUID **fixes**, à l'aide de `p_question` ou d'une mise à jour de l'identifiant après création, selon ce que permet `ecrire_question`. Ainsi le test « tout ou rien » vérifie réellement l'annulation : la question valide doit être traitée **avant** la question en brouillon dans l'ordre des UUID.
  - Vérifier `signalement.traite_par` = l'admin.
  - Envelopper le `select` nu de la ligne 44 dans une assertion.
  - Ajouter un appel avec `'{}'` par un non-admin, qui doit lever `acces_refuse` : il prouve que la garde du lot agit avant la boucle.
- [ ] **c. `garder_statuts`**
  - Dans une migration `20270112000002_garder_valide.sql`, recréer `prive.ecrire_question` à partir de son corps actuel (`20270105000003_garder_brouillon.sql`). La seule différence : `v_garder` est calculé **après** `perform prive.valider_question(p)`, et `garder_statut` accepte seulement un booléen JSON. Une autre valeur lève `question_invalide`, le code existant du validateur, à vérifier.
  - Tests ajoutés :
    - `"garder_statut":"oui"` lève l'erreur prévue ;
    - un appel éditeur (`p_editeur = true`) avec `garder_statut` ne garde rien ;
    - une question validée avec un signalement ouvert, plus `garder_statut`, plus une structure changée, donne une nouvelle version `a_relire`.
- [ ] **Vérifier** : `npm run db:reset && npm run test:db`. Prouver que chaque nouvelle assertion discrimine : retirer la garde visée, constater l'échec, puis rétablir. Noter le résultat dans le rapport.

### Task 4 : typographie des 140 anciennes questions BPH (6a)

**Problème :** les sources `bph:chN:quiz:*` et `bph:chN:bis:*` comptent environ 200 espaces normales avant « ? : ; ! » dans `enonce` et `explication`, alors que les nouvelles questions ont des espaces insécables.

- [ ] **Script ponctuel** `scripts/typo-anciennes-questions.ts` (non branché dans `package.json`). Il réécrit `contenu/1re-st2s/bph.json` en remplaçant l'espace U+0020 placée juste avant `? : ; !` par U+00A0, **uniquement** dans `enonce` et `explication` des questions dont la source contient `:quiz:` ou `:bis:`. Il ne touche jamais aux `propositions` ni aux `reponses_acceptees` : la structure resterait identique, mais une modification des propositions créerait une nouvelle version et masquerait la question aux élèves.
- [ ] **Vérification de l'import** : lancer `npm run import:contenu -- contenu/1re-st2s/bph.json --garder-statuts`. Le bilan attendu est `versionnee 0`, `cree 0`, et `modifiee` égal au nombre de questions touchées. Toutes ces questions restent `valide`, à vérifier par une requête de comptage avec la clé de service.
- [ ] **Contrôle** : `banque:verifier` de 1 à 7 passe toujours. Un `git diff --stat` ne montre que `bph.json`.
- [ ] **Commit** : « Harmonise la typographie des anciennes questions BPH ». Le script est commité avec, et le guide des auteurs le mentionne en une ligne.
